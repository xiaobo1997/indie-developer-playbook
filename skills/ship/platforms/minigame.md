# 平台管线 · 微信小游戏

> 与[小程序管线](miniprogram.md)同构（`miniprogram-ci` 同一套工具，`ci.upload` 支持 minigame 项目）。
> **本文只讲差异与那个最大的门槛：软著。**

## 硬门槛（预检项，比小程序多三行）

| 检查项 | 要求 | 说明 |
|---|---|---|
| **软件著作权** | 游戏提审需提供《计算机软件著作权登记证书》 | 申请周期 **1-3 个月**，¥500-1000（代理价，自己办更慢更省）；[中国版权保护中心](https://www.ccopyright.com.cn/)。**预检最大杀手：没有它一切免谈** |
| 类目与资质 | 游戏类目资质要求（出版备案等），个人主体可选类目受限 | 以 [微信官方](https://developers.weixin.qq.com/miniprogram/product/) 为准 |
| 虚拟支付 | 内购需企业主体 + 米大师通道；iOS 端另有虚拟支付限制 | 见 [mini-game 平台文档](../../../docs/10-platforms/wechat-game/mini-game.md) |
| 其余 | 同 miniprogram 全部预检项 | — |

## 与小程序管线的差异

| # | 步骤 | 谁 |
|---|---|---|
| G-00 | **预检时单独核软著状态**：无 → blocked，输出代办路径（材料/渠道/周期），产品先行转 Web/其他平台 | 🤖 |
| G-01 | 构建：游戏项目用 Cocos Creator / 原生小游戏构建产出，`ci.upload` 上传 | 🤖 |
| G-02 → G-06 | 与 miniprogram 的 M-02→M-06 相同（体验版→E2E→提审→轮询→发布） | — |

## E2E 验收（交付标准）

- [ ] 体验版真机可玩核心关卡/循环，帧率可接受
- [ ] 分享卡片、激励视频（如已接）真机正常
- [ ] 提审成功（审核单号在手）

## 现实建议（写进预检报告）

小游戏路线的启动顺序应该是：**软著申请（第 1 天）→ 开发与小程序管线并行 → 软著下来再提审**。让软著周期成为并行等待，而不是串行阻塞。个人主体小游戏变现受限（不能内购），变现规划回 [phases/08-iterate](../../../phases/08-iterate/README.md)。
