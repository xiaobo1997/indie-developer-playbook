# 01 - 独立开发者的心态

## 核心原则

### 1. 先发布，再完美 (Ship First)

> "如果你为自己使用感到骄傲，那就是发布的时机。" - Pieter Levels

**反模式**：
- 等所有功能都做好
- 等代码完美
- 等设计到位

**正确做法**：
- 80% 完成就发布
- 自己用一段时间
- 根据反馈迭代

### 2. 公开构建 (Build in Public)

**为什么**：
- 吸引早期用户
- 获得反馈
- 建立个人品牌
- 同行监督（让你坚持）

**怎么做**：
- Twitter / X 每日更新
- 即刻 / 朋友圈分享进度
- 周报 / Newsletter
- YouTube 视频

### 3. 解决自己的问题 (Scratch Your Own Itch)

**最佳产品**：你自己天天用的工具
- 你自己就是目标用户
- 你知道痛点
- 你的时间就是 deadline

**反模式**：
- 做"市场需要"但自己不用
- 跟风做热门赛道
- 为了融资做产品

### 4. 利润优先 (Profit First)

**Pieter Levels 的金钱原则**：
- 不融资
- 不烧钱
- 不雇人
- 不超过 6 个月没有收入
- 没有 MRR 不做下一个产品

**关键问题**：
- 第一个月能赚多少？
- 现金流是多少？
- 单位经济学是什么？

### 5. 保持简单 (KISS)

**做减法**：
- 一个核心功能
- 一个用户角色
- 一个变现方式
- 一个分发渠道

**反模式**：
- 一开始就做"平台"
- 支持所有用户
- 多种定价
- 多渠道分发

### 6. 长期主义 (Long-term)

**独立开发是马拉松**：
- 第一年：可能不赚钱
- 第二年：开始有稳定收入
- 第三年：可以全职
- 第五年：实现财务自由

**心态调整**：
- 把每个失败当学习
- 把每个反馈当礼物
- 把每个用户当朋友

## 决策框架

面对选择时问自己：

1. **这是我自己想用的吗？**
   - 否 → 不做
   - 是 → 继续

2. **这能 30 天内发布吗？**
   - 否 → 砍功能
   - 是 → 继续

3. **这能 30 天内有人付钱吗？**
   - 否 → 重新想定位
   - 是 → 干！

4. **我一个人能维护吗？**
   - 否 → 简化
   - 是 → 发布

5. **我愿意免费维护 5 年吗？**
   - 否 → 别做
   - 是 → 真爱，做！

## 时间管理

### 番茄工作法变体
- 25 分钟专注 / 5 分钟休息
- 每天 8 个番茄（4 小时深度工作）
- 每周 5 天

### 时间块（Time Blocking）
```
示例一天：
09:00-10:00  PM 工作（看数据、回邮件）
10:00-12:00  编码（核心功能）
13:00-14:00  营销（发推、写博客）
14:00-16:00  编码（修 bug、加功能）
16:00-17:00  客服（回用户问题）
```

### 周末休息
- 周六完全休息
- 周日只做规划（不写代码）

## 应对孤独

独立开发的常见心理问题：
- 没有同事
- 没有反馈
- 没有 deadline
- 容易自我怀疑

**解决方案**：
- 加入独立开发者社区（Indie Hackers、即刻、Twitter）
- 找一个 accountability partner（互相监督）
- 公开构建（建立外部 accountability）
- 必要时找心理咨询

---

## 失败的勇气

**所有成功的独立开发者都失败过**：
- Pieter Levels 失败过 30+ 个项目
- Marc Lou 失败过 5+ 个项目
- 大部分 SaaS 在第一年死掉

**如何失败得聪明**：
- 小投入试错
- 快速验证
- 30 天决定做不做
- 失败就转下个项目
