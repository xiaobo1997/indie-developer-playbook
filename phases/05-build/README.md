# 环节 05 · 开发实现（Build）

> **解决什么问题**：把任务卡变成每天可运行的产品。你的角色从"写代码的人"变成"验收代码的人"：AI 写，你验。本环节的纪律比技巧重要。

## 你要做什么

1. **每日节奏（贯穿 MVP 全程）**：早上取一张任务卡 → 喂给 AI（带上下文：AGENTS.md + 对应 SKILL/任务卡）→ 逐条验收完成标准 → 真机自测 → commit（信息写"做了什么+为什么"）→ 下一张。**一天结束时仓库里永远是一个能跑的版本。**
2. **验收而不是信任（核心习惯）**：AI 交付代码后，你按三步验收：
   - 跑起来：功能在模拟器 + 真机上符合任务卡完成标准
   - 看边界：空数据、断网、极端输入、iPhone SE 小屏
   - 读改动：git diff 过一眼，重点看有没有越界改动（动了任务卡之外的东西）
3. **测试策略（最低限度，别过度）**：
   - 纯逻辑（工具函数、词库处理、金额计算）写单元测试
   - 页面交互靠真机手测 + 每次发版前的[部署检查清单](../../skills/devops/deploy-checklist.md) ✅
   - 一条**关键路径清单**（打开 → 注册 → 核心功能 → 关闭）每次发版必走一遍
4. **上下文管理（AI 协作的关键）**：项目仓库里维护好 `AGENTS.md`；每个任务卡做完，把"决定/坑"追加到 AGENTS.md 或 notes——AI 换会话后依然延续约定，不重复踩坑。
5. **卡住超过半天就降级**：砍掉该功能的边缘细节，或换个更笨的实现。单人项目最贵的是"卡在一个不重要的点上三天"。

## 产出物

- 仓库：每天一个以上的 commit，主分支永远可运行
- `tasks.md`：任务卡逐张打勾
- 关键路径自测清单（发版前用）

## 完成标准

- [ ] 环节 02 的 MVP 任务卡全部通过验收
- [ ] 关键路径在真机上走通（新手机、未登录状态开始）
- [ ] 纯逻辑部分有单元测试且通过
- [ ] 仓库里没有 `console.log` 满天飞、没有硬编码的密钥
- [ ] M1「内部可用」达成：你自己愿意连续 3 天真实使用它

## 常见陷阱

- **和 AI 结对变成"生成-粘贴-祈祷"**：不验收就合并，bug 会复利。验收三步是硬纪律。
- **重构上瘾**：任务卡之外顺手"优化"——范围蔓延是延期第一原因。想重构？写张新卡排进明天。
- **只在模拟器测**：小程序模拟器与真机的差异（滚动、手势、字体、授权弹窗）足够让你提审后才发现致命 bug。
- **无 Git 习惯**：一天一个 commit 是底线；"大干三天一提交"等于没有版本控制。
- **过早引入复杂架构**：状态管理上 Redux、目录按 DDD 分层……第一版只需要"简单到不需要解释"的结构。

## 小程序主线注意点

- **真机调试用「真机调试 2.0」**：开发者工具里开真机调试，能看真机上的 console 与网络请求，排查线上问题的基础功。
- **授权与隐私接口**：`getUserProfile`、位置、相册等接口触发授权弹窗，要在用户有明确动机的场景里请求，且按官方要求配置[隐私保护指引](https://developers.weixin.qq.com/miniprogram/dev/framework/user-privacy/)（以官方为准），否则接口不生效。
- **分包提前想**：如果主包逼近 2M，把低频页面拆[分包](https://developers.weixin.qq.com/miniprogram/dev/framework/subpackages.html)（以官方为准）；大资源（词库/图片/音频）一律放云存储，运行时拉取。
- **云函数本地能跑 ≠ 线上能跑**：云函数有独立的部署与权限体系，改完记得「上传并部署」，线上测试走测试环境。
- **基础库版本**：用了较新的 API 时，在 `app.json` 配最低基础库版本，并在 README 记一笔——这是"真机行为不一致"的高频原因。
