# Skill: 任务拆分（Task Splitter）

> 角色划分参照 obra/superpowers 与 indie-developer-playbook 的 7 角色。
> **架构约束见 [ADR-0005](../../docs/decisions/0005-roles-as-independent-skill-trees.md)：本技能不调度、不派发任何 Agent，只产出任务卡。**
> 职责：拆任务 → 标依赖 → 定验收标准 → 写交接契约。不写代码。

## 任务目标

把一个大功能拆成若干张任务卡，每张卡对应一个角色、一件事、一条可核对的完成标准。

## 输入

1. 用户需求（一句话描述）
2. 项目仓库的 AGENTS.md
3. 相关的现状代码

## 输出

```
## 任务卡
- [ ] 前端：做什么 → 完成标准
- [ ] 后端：做什么 → 完成标准
- [ ] DevOps：做什么 → 完成标准
- [ ] 测试：做什么 → 完成标准

## 执行顺序
哪些必须串行（有依赖，说明原因），哪些可以任意顺序

## 交接契约
每张卡交付时，交出去的是什么文件、什么格式

## 验收标准
每个角色的交付物按什么标准验收
```

## 执行步骤

1. 读 AGENTS.md + 相关代码，确认技术栈
2. 拆任务：按角色分配（前端 / 后端 / DevOps / 测试 / 调试 / 审查），**一张卡只做一件事**
3. 标依赖：哪些必须先做、哪些可以任意顺序。**不预设并行**——一次推进一张卡，顺序由执行者决定
4. 定验收标准：每条都要能回答「怎么算做完」，不能写「做完了」
5. 写交接契约：每张卡交付什么格式的文件给下一个角色（这是角色之间唯一的衔接方式）

## 检查清单

- [ ] 每张卡只对应一个角色、一件事
- [ ] 依赖关系标清，且写明了原因
- [ ] 每条完成标准可核对
- [ ] 每张卡写清了交给下一个角色的是什么文件

## 边界（不要做什么）

- 不调度、不派发、不启动任何 Agent 或子进程
- 不写代码
- 不替用户做技术选型（有争议时问用户）
- 不预设执行方式是并行的——**一次一张卡，验收通过再领下一张**
- 不使用任何 harness 专属语法（slash command、`delegate_task`、子代理调度、专属变量）
