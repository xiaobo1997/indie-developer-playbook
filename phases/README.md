# 🧭 环节路线：一个人从想法到收益的完整地图

> **一个人 = 一个团队**。这份地图回答一个问题：独立开发到底要做哪些事？按什么顺序做？
> 每个环节 = 一个目录 = 一份说明 + 外部参考 + 一个可交给 AI 执行的标准技能（SKILL.md）。

## 8 个环节

| # | 环节 | 回答的问题 | 核心产出物 |
|---|---|---|---|
| [01](01-validate/) | **需求验证** | 这个需求是真的吗？有人愿意用/付钱吗？ | 一页验证报告（做/不做/改了再做） |
| [02](02-spec/) | **产品定义** | 做什么、不做什么、多久做完？ | 一页 PRD + 拆到「≤1 天」的任务清单 |
| [03](03-design/) | **UI/UX 设计** | 每个页面长什么样？用什么组件拼？ | 页面清单 + 低保真草图 + 主题 |
| [04](04-setup/) | **技术选型与脚手架** | 用什么技术栈？架子搭在哪？ | 可运行、可真机预览的空项目 |
| [05](05-build/) | **开发实现** | 怎么把任务清单变成可用产品？ | 每天可运行的产品 + 测试 |
| [06](06-release/) | **部署与上线** | 怎么合规地发布给用户？ | 通过审核的正式版本 + 监控 |
| [07](07-launch/) | **发布与增长** | 第一批 100 个用户从哪来？ | 发布计划 + 持续的内容渠道 |
| [08](08-iterate/) | **数据迭代与变现** | 用户用得如何？怎么赚到钱？ | 周复盘记录 + 变现通道上线 |

**用法**：第一次走按 01→08 顺序；产品上线后进入 07⇄08 的循环（每周复盘 → 下周迭代 → 持续增长）。

## 两条线：环节主线 × 工具生态

环节和工具是**两个独立的维度**，不要互相替代：

| | 管什么 | 会不会过时 |
|---|---|---|
| **环节主线**（`README.md` / `SKILL.md`） | 什么时候做什么、产出什么 | 慢。三年后这套流程还成立 |
| **工具生态**（`references.md` 里的同名小节） | 现在有什么能拿来用 | 快。会被收购、关停、改价 |

每个环节的 `references.md` 都含一节「**工具生态**」。列工具不是让你都用上，而是让你知道**这个行业已经把哪些重复劳动做成了产品**——知道有什么，才知道自己不用造什么；看工具的迭代方向，也能看出这个行业在往哪走。

工具条目统一三列：**工具 / 干什么 / 什么时候用**。收录前逐个实测可访问性（ADR-0004），价格与可用性以官网为准。

## 三件套约定

每个环节目录固定含三个文件，模式固定后你可以照抄模板新增环节：

```
01-validate/
├── README.md     # 说明（人读）：做什么/产出物/完成标准/陷阱/小程序注意点
├── references.md # 参考（外链）：开源仓库、官方文档、成功案例
└── SKILL.md      # 技能（AI 执行）：交给 Claude Code / Codex / Cursor / ZCode 等任何代理
```

**把环节交给 AI 干活**：对任何编码代理说「阅读 phases/02-spec/SKILL.md 并执行，输入是我的想法是……」即可。SKILL 之间是流水线——上一环节的输出就是下一环节的输入。

**记录你的学习笔记**：实操中的踩坑记到对应环节目录的 `notes.md`（个人日志，不追求格式），值得固化为方法的再升级进 README 或 ADR。

## 从零开始：自检清单（我缺什么？）

从零学独立开发，最怕的不是难，是**不知道自己缺什么**。逐环节问自己，答不上来的就是缺口：

**01 验证**
- [ ] 我能一句话说清：什么人、在什么场景、有什么痛点？
- [ ] 我和至少 3 个目标用户聊过吗（不是朋友客套）？
- [ ] 竞品有哪些？我看过至少 3 个同类产品吗？

**02 定义**
- [ ] 我有一页纸 PRD 吗？
- [ ] 任务拆到每个 ≤1 天了吗？
- [ ] MVP 里每个功能都能回答「砍掉会丢用户吗」吗？

**03 设计**
- [ ] 我有完整的页面清单吗（几页、每页干什么）？
- [ ] 我知道每类页面用哪个现成组件库拼吗？
- [ ] 我抄了几个成熟产品的同类页面（Mobbin/竞品）？

**04 脚手架**
- [ ] 小程序 AppID 注册了吗？个人主体还是企业主体（影响支付）？
- [ ] 微信开发者工具装好、Hello World 真机预览跑通了吗？
- [ ] 后端方案定了吗（云开发 / 自建 / BaaS）？

**05 开发**
- [ ] 仓库里有 AGENTS.md 给 AI 的约定吗？
- [ ] 每天结束时都有一个「能跑的版本」吗？
- [ ] 关键路径（注册、核心功能、支付）有测试吗？

**06 上线**
- [ ] 服务器域名 HTTPS + ICP 备案 + 小程序后台合法域名，三者都配了吗？
- [ ] 类目选对了吗？需要前置资质的类目查过了吗？
- [ ] 常见审核被拒原因（诱导分享、类目不符、隐私声明缺失）排查过吗？

**07 增长**
- [ ] 第一批 100 个用户的具体渠道是哪几个？
- [ ] 我在公开构建吗（即刻/小红书/推特持续发进度）？
- [ ] 小程序名称、简介的关键词优化做了吗（微信搜索是免费流量）？

**08 迭代变现**
- [ ] 我知道自己的北极星指标吗（周活？留存？付费率？）
- [ ] 变现方式想清楚了吗？——⚠️ 个人主体小程序**不能开通微信支付**，见下方硬知识第 1 条
- [ ] 有每周复盘的习惯吗（数据 → 决策 → changelog）？

## 小程序主线：最容易缺的 8 件硬知识

> 规则类内容以官方文档为准：[小程序开发框架](https://developers.weixin.qq.com/miniprogram/dev/framework/) · [微信支付](https://pay.weixin.qq.com/)

1. **主体决定变现上限**：个人主体免费、注册快，但**不能开通微信支付**，部分类目（电商、社交直播等）不可选；企业/个体工商户主体可开通支付（认证约 300 元/年，以官方为准）。**想收费又想个人开发**：先个人主体上线验证，有收入再升级主体，或引导用户到 Web 端支付。
2. **类目与资质**：医疗、教育、金融等类目需要前置资质证明，选错类目直接被拒审。注册时就要想清楚产品定位对应的类目。
3. **服务器域名三件套**：小程序请求的后端域名必须 **HTTPS + ICP 备案 + 在小程序后台配置 request 合法域名**。用微信云开发可以绕开这套（官方托管），这是个人开发者最快的路。
4. **包体积限制**：主包有上限（2M），启用分包可扩大总体积（具体上限以[官方文档](https://developers.weixin.qq.com/miniprogram/dev/framework/subpackages.html)为准）。词库、图片等大资源放云端，别塞进代码包。
5. **审核节奏**：每次发正式版都要审核（通常几小时到 1-2 天），要习惯「体验版自测 → 提审 → 发布」的节奏；重大更新别卡在节假日提审。版本可以回滚。
6. **iOS 虚拟支付限制**：iOS 端虚拟商品（会员、解锁）受苹果规则约束，小程序内直接卖虚拟内容有被拒风险，常见做法是 iOS 引导到 Web/兑换码（以官方最新规则为准）。
7. **流量主门槛**：开通小程序广告（流量主）需累计独立访客达标（UV ≥ 1000，以后台要求为准）。这是个人主体**唯一**的原生变现通道，也是「先做量再变现」路线的依据。
8. **隐私合规**：采集用户信息（头像、昵称、手机号）的接口要求配置[隐私保护指引](https://developers.weixin.qq.com/miniprogram/dev/framework/user-privacy/)并在后台声明，缺失会被拒审或接口不可用。

## 知识积累飞轮（怎么一直迭代这个仓库）

```
做产品（小程序实操）
   ↓ 踩坑
记 notes.md（环节目录内，随手记）
   ↓ 沉淀
每周复盘（用 phases/08-iterate/SKILL.md）：
   值得固化的方法 → 更新环节 README
   外部好资源 → 更新环节 references.md
   重复性工作 → 写成/升级 SKILL.md
   结构性决定 → 写 ADR 进 docs/decisions/
   ↓ 记账
CHANGELOG.md 记一笔
   ↓ 循环
下一个环节……
```

仓库和产品一起长：**产品上线的每一步，都在给手册添一块砖。**
