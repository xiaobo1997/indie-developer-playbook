# 12 · 工具栈角色目录

> 工具栈是横切性资源：它不属于某个环节，但每个环节都要用。原则：**先用免费的、开源优先、少即是多、可迁移**——工具服务于流程，流程不为工具让路。
> 完整工具清单见 [stack.md](stack.md)；本页只管"怎么选"。

## 这个角色负责什么

| 负责 | 不负责 |
|---|---|
| 工具选型决策（5 问法）与成本控制 | 用工具产出业务内容（各角色的活） |
| 季度工具巡检（还在吗？还值吗？） | 引入新工具跟风（新工具先观察 3 个月） |
| 开源替代评估（压低月费） | 替环节定流程（流程在 phases/，工具跟着流程走） |

**边界判定**：产出物是"选型决定 + 成本表"；产出物是"业务文档"就越界了。

## 独立跑完「工具选型」的流程

| 步 | 做什么 | 产出 | 耗时 |
|---|---|---|---|
| 1 | 从 stack.md 的「起步版（$0/月）」组合开始 | 初始工具清单 | 30 分钟 |
| 2 | 用痛了才换：每件工具记一条"换掉它的条件" | 工具台账 | 随手 |
| 3 | 每季度巡检：还活着吗？免费额度还够吗？有开源替代吗？ | 巡检记录 | 每季度 1 小时 |
| 4 | 想加新工具：过 5 问（解决具体痛点？免费试用？可导出？社区活？3 年后还在？） | 加/不加 + 理由 | 每件 15 分钟 |

**两条线的分工**（与 [phases/README](../../phases/README.md) 的约定一致）：**环节主线**（什么时候做什么，慢变量）vs **工具生态**（现在有什么能用，快变量）。工具会被收购、关停、改价——仓库地址比 SaaS 官网活得久。

## 收什么 → 交什么

| 上游交给我 | 我交给下游 |
|---|---|
| 各角色的工具痛点（"X 环节特别烦 Y"） | → 全体角色：选定工具与配置规范 |
| 财务角色：成本红线 | → 财务角色：月度成本表 |
| 开源社区：新替代品信息 | → references：验证过的工具条目 |

## 真实参考（不用凭空想象）

- 完整清单：[stack.md](stack.md)（按角色分组的推荐组合，含起步/增长/规模三档月费）
- 开源替代：[awesome-solo-founder-oss](https://github.com/princepal9120/awesome-solo-founder-oss)（★66，MIT）逐岗位清单；找其他领域从 [sindresorhus/awesome](https://github.com/sindresorhus/awesome)（元目录）进
- 免费开源 SaaS 套件：[wasp-lang/open-saas](https://github.com/wasp-lang/open-saas)（鉴权/邮件/Stripe/后台全带）
- 各环节"现在能用的工具"：见 [phases/*/references.md](../../phases/README.md) 的「工具生态」小节（收录前实测过可访问性）
- 本仓库技能：工具选型无独立 skill——5 问法是决策清单不是工作流；巡检动作并进 [phases/08-iterate/SKILL.md](../../phases/08-iterate/SKILL.md) 的季度动作

## 新手最容易踩的坑

| 坑 | 为什么会踩 | 怎么避 |
|---|---|---|
| 工具控（收集器当生产力） | 收集的快感 | 新工具先写"换掉它的条件"再引入 |
| 为工具改流程 | 大厂在用什么就上什么 | 流程（phases/）是主，工具是仆 |
| 冲动付费 | 年付折扣的紧迫感 | 先用免费版踩两周痛点再掏钱 |
| 数据被锁死 | 没查导出功能就重度用 | 5 问法第 3 条：可迁移 |
| 忽视工具死亡 | SaaS 被收购/关停是常态 | 季度巡检 + 关键资产选开源可自托管 |
