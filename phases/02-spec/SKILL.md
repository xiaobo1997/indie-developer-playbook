# 任务目标

基于环节 01 的验证结论（目标用户 + 核心痛点 + 平台），产出三件套：**一页 PRD、任务卡清单、里程碑计划**。核心纪律是砍范围：每一项都要通过"砍掉测试"。

# 输入

1. 环节 01 的验证报告（用户、痛点、平台、结论）
2. 用户补充的功能愿望清单（有多少给多少）
3. 时间预算（例如"4 周业余时间"，没有就按 4 周假设并向用户确认）

# 输出（严格按此结构交付）

```
## PRD（一页）
- 产品一句话：为【谁】解决【什么】，核心价值是【什么】
- 目标用户与场景（来自验证报告）
- MVP 必有清单（每项一行：功能 + 为什么没有它产品不成立）
- v2 再说清单（想到了但砍掉 + 砍的理由）
- 页面结构粗稿：页面列表 + 每页一句话职责（小程序注明 Tab 数量与层级）
- 非目标：明确写出"这个版本不做的事"

## 任务卡
| 编号 | 任务 | 完成标准（可验收） | 预估 | 依赖 |
（每张 ≤1 天；完成标准写成可勾选的行为，如"列表页滚动加载 20 条/页，空态显示引导文案"）

## 里程碑
M1 内部可用（日期）/ M2 提审版（日期）/ M3 正式发布（日期）
每个里程碑包含哪些任务卡编号。

## 风险
3 条以内：最可能让计划翻车的事 + 对策
```

# 执行步骤

1. 从验证报告提取目标用户、核心痛点、平台约束，作为 PRD 的锚
2. 把用户的愿望清单分成「MVP 必有 / v2 再说」，每一项做砍掉测试：**砍掉它会丢用户吗？**答"不会"进 v2
3. 按「用户旅程 → 页面 → 功能点 → 任务卡」的顺序拆任务，每张卡检查：能否被一个 AI 代理在单次会话内完成并自验？
4. 把任务卡分配到 3 个里程碑，按时间预算倒排日期；超预算时**砍范围不延日期**，砍不了的向用户亮红灯
5. 写非目标与风险

# 检查清单（输出前自检）

- [ ] PRD 不超过一页（约 40 行），非目标一节非空
- [ ] 每张任务卡有可勾选的完成标准，没有"完成前端"这种粒度
- [ ] 里程碑有具体日期，且总量不超出用户给的时间预算
- [ ] 涉及登录/支付/消息等平台能力的任务卡，标注了依赖与"以官方文档为准"

# 边界（不要做什么）

- 不质疑环节 01 的结论（要推翻请回到环节 01 重做）
- 不写代码、不选具体技术栈（那是环节 04；任务卡只描述"做什么与验收"，不描述"怎么实现"）
- 不为 v2 功能设计任何细节
