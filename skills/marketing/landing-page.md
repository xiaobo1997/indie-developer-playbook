# 任务目标

为一个已定位的产品生成**落地页的完整文案与区块规划**：7 个必备区块各写什么、按什么顺序、CTA 指向哪。产出可直接交给开发照做，不需要设计师。

# 输入

1. 产品一句话定位（帮谁用什么方式完成什么事）+ 目标用户
2. 可用素材：截图/演示视频（没有就标注"需用户制作"）、真实数据（有则用，没有不用编）
3. CTA 目标：引导到小程序码 / 注册 / 下载 / 邮件订阅

# 输出（严格按此结构交付）

```
## 区块规划（自上而下）
| # | 区块 | 目的 | 一句话说明 |
1 Hero（价值主张）/ 2 截图或演示 / 3 社会证明 / 4 核心功能 3-5 条 / 5 价格 / 6 FAQ / 7 CTA

## 完整文案
每区块的成稿文案（中文为主；Hero 给 3 个候选标题供 A/B）
- Hero 标题：讲结果不讲技术（"三分钟完成 X" 而非 "基于 XX 架构的 X 平台"）
- 功能：每条 = 用户动作 + 得到的结果，不写功能名词堆砌

## FAQ（5-7 条）
真实顾虑（数据安全？收费？与竞品区别？），每条两句话答完

## 开发交接
区块对应的实现建议（组件库现成组件 / 纯文案块），移动端单列可直接用
```

# 执行步骤

1. 先读 [docs/07-marketing/marketing.md](../../docs/07-marketing/marketing.md) 的落地页 7 要素与转化率基准
2. Hero 先写：一句话 = 目标用户 + 结果 + 时间/成本优势；写不出就回环节 02 找定位
3. 社会证明诚实原则：没有用户数就不用该区块或换成"构建过程/截图实拍"，**不编造用户评价**
4. FAQ 从真实反馈里挑（没有反馈就写你自己决定用之前会问的问题）
5. 价格透明；免费产品把 CTA 写成"立即使用"+ 小程序码位
6. 全文自检：把"我们的"全部改成"你的"视角；删掉所有形容词堆砌

# 检查清单（输出前自检）

- [ ] 7 区块齐全且顺序符合"先结果后功能"
- [ ] 没有编造的数据、评价、用户数
- [ ] Hero 有 3 个可 A/B 的候选
- [ ] CTA 明确且与产品形态匹配（小程序码 / 注册 / 订阅）
- [ ] 无实现难度的花哨区块（动效/插画仅在有现成素材时建议）

# 边界（不要做什么）

- 不写代码（产出文案与区块规划；实现走 Web 路线脚手架或 `tailwind-setup`）
- 不做 SEO 关键词研究（那是发布后的长期活，见 docs/07 的 SEO 小节）
- 不适用：小程序本身（落地页是 Web 引流页，小程序内页直接用组件库）；想做的其实是产品介绍幻灯片（那是 `press-kit` 的事）
