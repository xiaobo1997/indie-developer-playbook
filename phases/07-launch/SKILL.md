# 任务目标

接环节 06（已正式发布），产出：**发布弹药包 + 渠道发布计划 + 4 周内容日历**。一切内容遵循「讲故事 + 求反馈」，禁止夸大宣传与违规诱导分享的玩法。

# 输入

1. 产品信息：一句话定位、目标用户、核心功能（来自 PRD）、当前真实数据（若有，没有就用"第 1 天"叙事）
2. 目标用户聚集地（用户若不知道，由代理按用户画像推荐渠道）
3. 用户能投入的营销时间（每天 15 分钟？每周半天？）

# 输出（严格按此结构交付）

```
## 发布弹药包
- 30 秒介绍（痛点故事版，150 字内）
- 三种长度的帖子文案：微信群短版（50 字）/ 社区长版（300-500 字）/ 公开构建版（100 字）
- 截图清单：需要哪几张图、每张展示什么（标注"需用户真机截图"，代理不伪造图）

## 渠道发布计划
| 渠道 | 为什么适合（与用户画像的关系） | 发什么版本 | 发布时机 |
（3-5 个渠道；每个附一条发帖注意事项，如 V2EX 分享创造节点规则）

## 4 周内容日历
按用户可投入时间排：每周 3-5 条，每条给主题 + 一句话角度
第 1 周以"发布+求反馈"为主，第 2-4 周转"进度/踩坑/数据"叙事

## 合规提醒
与诱导分享/夸大宣传相关的红线，标注以平台官方规范为准
```

# 执行步骤

1. 从产品信息提炼「痛点 → 方案 → 证据」叙事；没有数据就用构建过程当证据
2. 写三种文案：短版给微信群（一眼看懂+二维码位），长版给社区（背景故事+功能+求反馈），进度版给持续更新
3. 渠道选择必须论证"你的目标用户为什么在这"，不推荐与画像无关的大渠道
4. 内容日历尊重时间预算：宁可每周 2 条可持续，不要每周 7 条三天放弃
5. 合规自查：文案中不出现"转发才能""集赞解锁"类机制；声明以各平台规范为准

# 检查清单（输出前自检）

- [ ] 文案有具体场景与痛点，没有"功能强大""效率神器"这类空词
- [ ] 每个渠道都有"为什么是它"的论证
- [ ] 内容日历总量匹配用户时间预算，且前 2 周具体到可直接照抄发布
- [ ] 截图/视频等代理无法生成的素材，明确标注由用户制作
- [ ] 无诱导分享、无编造数据/用户评价

# 边界（不要做什么）

- 不修改产品代码（发现分享卡片等可优化点，登记为建议）
- 不承诺增长数字（"预计带来 XX 用户"这类话不说）
- 不建议买量、刷量、互推群等污染数据的手段
