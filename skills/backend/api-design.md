# 任务目标

接 PRD（功能范围 + 数据模型草案），产出一份**前后端都认可的 API 契约**，让前端可以 mock 着开发、后端照着实现。小程序云开发路线则产出"集合结构 + 云函数清单"作为等价契约。

# 输入

1. PRD（用户故事 + 功能范围 + 数据模型节）
2. 后端形态：REST API（自建/Supabase）或微信云开发（云函数 + 云数据库）
3. 鉴权方式（Session/JWT/openid；不确定按 PRD 平台默认）

# 输出（严格按此结构交付）

```
## 资源与端点表
| 方法 | 路径 | 用途 | 鉴权 | 请求 | 响应 | 错误码 |
（REST 风格；命名遵循 docs/05-backend：复数名词、kebab-case）

## 核心端点详情
对 2-3 个核心端点展开：请求示例 JSON / 成功响应示例 / 每个错误码的含义

## 错误码规范
统一错误结构 { error: { code, message } } + 本项目错误码清单

## 云开发等价契约（若适用）
| 集合 | 关键字段 | 权限 | 读写的云函数 |
（含集合权限说明：仅创建者可读写 / 所有用户可读等）

## 分页与列表约定
游标还是页码；默认页大小；排序字段
```

# 执行步骤

1. 先读 [docs/05-backend/backend.md](../../docs/05-backend/backend.md) 的 API 设计与鉴权小节，遵循其命名与响应格式约定
2. 从每条用户故事反推端点：故事里"我想做什么" → 一个写操作；"我想看什么" → 一个读操作
3. 检查数据模型：每个端点的字段都要能在 schema 里找到；找不到 → 回 `db-schema` 补模型，不在契约里即兴加字段
4. 写错误码：≥4xx 的每种失败都给码与文案；不返回堆栈与内部信息
5. 云开发路线：一个业务动作 = 一个云函数（粒度对齐任务卡），写清每个集合的权限模式（安全清单要求默认最小权限）
6. 产出交给前端前自检：前端拿着这份契约能否不问后端就 mock 出全部页面？

# 检查清单（输出前自检）

- [ ] 命名一致：复数、名词、无动词路径（`GET /getUser` ❌）
- [ ] 每个端点都有鉴权标注与错误码，没有"永远 200"
- [ ] 字段与数据模型一一对应，无悬空字段
- [ ] 云开发路线写清了每个集合的权限（不是全开）

# 边界（不要做什么）

- 不写实现代码（契约先行；实现用 `phases/05-build/SKILL.md`）
- 不设计数据库索引与性能优化（用 `db-schema`）
- 不适用：MVP 只有十几个端点且单人开发（契约可以简化成一页表，但格式不变）；已经用 Supabase 自动生成 API（契约改为"表结构 + RLS 策略"文档）
