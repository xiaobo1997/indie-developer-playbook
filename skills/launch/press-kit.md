# 任务目标

为已上线的产品生成**一页式媒体资料包（media kit）**：记者、播客主、社区管理员、潜在合作方在 2 分钟内拿到关于你产品的全部事实与素材。放在网站 `/press` 或仓库 `/docs` 下长期可引用。

# 输入

1. 产品事实：正式名称、一句话定位、上线日期、平台（小程序/Web/App）、价格、链接
2. 创始人信息：署名偏好、一句话背景、社交账号
3. 素材：Logo（SVG+PNG）、3-5 张产品截图、演示视频（没有就列为"需制作"）

# 输出（严格按此结构交付）

```
## 事实表（30 秒可读完）
产品名 / 一句话 / 上线日期 / 平台与价格 / 差异化两点 / 联系方式与回复时限
——每条都是可引用的短句，记者可直接摘抄

## 创始人简介
第一人称 50 字 + 第三人称 80 字两个版本（后者给媒体直接用）

## 素材清单
| 素材 | 规格 | 下载/查看 | 用途建议 |
Logo 深浅底两版 / 截图（首屏+核心功能）/ 演示视频 ≤60s / 数据一张图（有公开数据才放）

## 可讲的三个故事角度
给记者/播客的选题建议：个人问题→产品 / 单人开发方法论 / 某个具体取舍——每个角度两句话梗概

## 引用规范
名称大小写、别称禁用、Logo 使用边界（不拉伸不改色）
```

# 执行步骤

1. 先读 [docs/13-cases/case-studies.md](../../docs/13-cases/case-studies.md)——成功产品的资料页只放事实与故事角度，不放形容词
2. 事实表逐条自查"这句能被直接引用吗"：能 → 留；不能 → 改写成能
3. 一页纪律：整包 1 页 HTML/MD 为限，超了砍素材不放废话
4. 数据诚实：没有公开可验证的数据就整块不放，不写"数千用户"这类模糊词
5. 素材缺口（视频/深浅 Logo）如实列"待制作"，不占位假文件

# 检查清单（输出前自检）

- [ ] 事实表每条都能被直接引用，无形容词堆砌
- [ ] 无编造数据；无数据则该区块整块缺席
- [ ] 素材缺口如实标注"需制作"
- [ ] 一页放得下（≤80 行渲染后）

# 边界（不要做什么）

- 不群发媒体（产出资料包，发不发、发谁是用户的公关决策）
- 不写新闻稿正文（那是接到兴趣后的下一步；一页 kit 是入口不是全文）
- 不适用：产品没上线（先上线）；想要融资 BP（独立开发者路线默认不融资，且 BP 是另一个文体）
