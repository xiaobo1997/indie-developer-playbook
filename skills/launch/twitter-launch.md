# 任务目标

把一次产品发布写成 **1 条主推 + 4-6 条跟帖的串（thread）**：首句钩子、问题叙事、产品展示、CTA。产出中英双版（英文面向 #buildinpublic 圈层）。同时是 X 之外平台的文案母版。

# 输入

1. 产品一句话定位 + 目标用户痛点（来自 PRD/验证报告）
2. 发布形式：全新发布 / 大版本更新（叙事结构不同）
3. 素材：截图/GIF/短视频（标注"需用户录制"，代理不伪造）
4. 创始人一句真话（为什么做它——个人故事是 X 的通货）

# 输出（严格按此结构交付）

```
## 主推（钩子）
英文版 + 中文版，各 ≤280 字符
结构二选一：痛点开场（"Every time I X, I lost Y."）/ 反直觉开场（"I shipped X in N days. Here's what it does:"）

## Thread（4-6 帖）
1 问题放大 → 2-3 产品是什么+截图位 → 4 技术或设计取舍（给同行看的干货）→ 5 CTA（链接+求反馈）

## 配图清单
每帖需要什么图（产品截图第几屏/录制哪段 GIF），标注"需用户制作"

## 首小时动作
发布后 60 分钟内：回复所有评论 / 转发自己的帖一次（不刷量）/ 私信 3 个真实支持者
```

# 执行步骤

1. 先读 [docs/07-marketing/marketing.md](../../docs/07-marketing/marketing.md) 的公开构建小节与 [docs/01-mindset/mindset.md](../../docs/01-mindset/mindset.md)（真实进展比宣传结果有共鸣）
2. 首句是 90% 的功夫：写 5 个候选钩子，挑"同行为会停下刷屏"的那个，删掉所有形容词
3. 每帖一个信息点，帖尾用"↓"衔接；不塞话题标签进正文（放最后一帖，≤3 个）
4. CTA 求反馈而非求转发（"What would you remove?" 比 "Please RT" 引来真对话）
5. 中英两版不是翻译关系：中文版可带更多背景叙事，英文版更短更直接

# 检查清单（输出前自检）

- [ ] 首句没有"我们很高兴地宣布"式套话
- [ ] 每帖 ≤280 字符，配图位标注"需用户制作"
- [ ] CTA 是求反馈，不是拉票转发
- [ ] 没有 P0 级夸张（"颠覆""第一"）——被同行戳破一次，信任就没了

# 边界（不要做什么）

- 不做买粉/互推群/刷量（污染环节 08 的所有决策数据）
- 不代发（产出文案与排期，发布动作是人的真实账号行为）
- 不适用：目标用户不在 X（中文工具用户主阵地在即刻/小红书，见 docs/07 渠道分级）；账号零粉丝且零互动历史（先公开构建 2 周再发布，冷号发产品等于对着空气喊）
