# 任务目标

对用户提供的**页面截图、线框图或 HTML 预览**做一次评审，输出按严重程度排序的问题清单，每个问题附具体改法。不夸奖、不泛泛建议。

# 输入

1. 页面截图 / 线框图 / 可运行的预览（有多少给多少；多页时逐页评）
2. 使用的组件库（TDesign / Vant / shadcn…；用于判断是"偏离组件库默认"还是"组件库本身的限制"）
3. 页面职责一句话（这页用户进来干什么）

# 输出（严格按此结构交付）

```
## 评审结论
一句话：可以开发 / 建议修改后再开发（二选一）

## 问题清单（按严重度排序）
### P0/P1/P2-编号：[问题一句话]
- 维度：层级 / 间距 / 对齐 / 对比度 / 三态 / 极端数据
- 证据：图上具体位置描述
- 改法：改哪个值、改成什么（引用组件库的现成属性优先）

## 做得对的（≤3 条，一句话一条，防止改错方向）
```

# 执行步骤

1. 先读 [docs/03-ui/ai-as-designer.md](../../docs/03-ui/ai-as-designer.md) 的「评审 prompt」一节——本技能是它的可执行版
2. 灰度化检查：想象截图转黑白，信息层级还清楚吗？不清楚 → 层级问题是 P0
3. 六维逐项过：信息层级 / 间距一致性 / 对齐 / 对比度 / 空载错三态 / 极端数据（长文本、空列表、大数字）
4. 对照组件库默认值：随手自定义的值都是嫌疑点，给出"改回默认"或"全局统一为 X"的改法
5. 每个问题给可执行改法（具体数值或组件属性），禁止"建议优化"

# 检查清单（输出前自检）

- [ ] 结论只有二选一，没有"整体不错但可以更好"
- [ ] 每个问题都有证据（位置）和改法（数值）
- [ ] 三态没有漏查；长文本/空列表场景查过
- [ ] 夸奖 ≤3 条且各一句话

# 边界（不要做什么）

- 不重新设计（只评审给定方案，出方案用 `phases/03-design/SKILL.md`）
- 不评代码质量（看图不看码）
- 不适用：还没有可视产物（先用 wireframe-preview.html 画出来）；要评的是流程而非界面（用 5 人测试，见 docs/03-ui/prototype-first.md）
