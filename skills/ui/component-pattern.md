# 任务目标

接一份页面清单（pages.md）+ 一个选定组件库，输出**每页每区块的组件映射表**，区分"现成组件 / 简单组合 / 必须自写"三类，作为开发前的最后一张图纸。

# 输入

1. 页面清单（页面 / 职责 / 大致区块；没有就先用 [wireframe-preview.html](../../templates/wireframe-preview.html) 画）
2. 选定组件库：TDesign / Vant Weapp / WeUI（小程序）或 shadcn/ui（Web）——**只用一个**
3. 平台（小程序组件库与 Web 组件库**不通用**，先确认）

# 输出（严格按此结构交付）

```
## 组件映射表
| 页面 | 区块 | 组件（库名 + 组件名） | 类型 | 备注 |
类型三选一：✅现成 / 🔧组合（写清由哪几个现成组件拼）/ ⚠️自写（说明为何绕不开）

## 自写组件清单
每条：组件名 / 最小功能 / 用到的原生元素（小程序）或基础标签（Web）

## 库能力缺口
组件库覆盖不了的需求 1-3 条 + 建议的降级方案
```

# 执行步骤

1. 先读 [docs/03-ui/ui-reference-projects.md](../../docs/03-ui/ui-reference-projects.md) 的「6 种页面骨架」——先认出每页属于哪种骨架，再映射组件
2. 基于你对所选组件库的知识映射；**不确定组件是否存在时，标注 `[需核实]` 并给出核实方法（查组件库文档对应章节），不要假装存在**
3. 区块匹配不上现成组件时，先试着用组合解决（如"列表项 = Cell + Badge + Thumbnail"），组合不行才自写
4. 自写组件尽量用平台原生元素拼，不引第三方
5. 三态（空/载/错）也要有组件映射（骨架屏组件、Empty 组件、Toast/Dialog）

# 检查清单（输出前自检）

- [ ] 没有编造的组件名；不确定的都标了 `[需核实]`
- [ ] 自写组件数量 ≤3（超过说明选错了组件库或页面职责不清）
- [ ] 每页的空/载/错三态都有映射
- [ ] 全程只用了一个组件库，没混第二家

# 边界（不要做什么）

- 不写代码（映射表是图纸，写代码是前端角色的事）
- 不换组件库、不混用两家（发现覆盖不足，输出缺口清单交用户决策）
- 不适用：还没有页面清单（先用 `phases/03-design/SKILL.md` 生成）；目标是 Web 且想用 AI 生成 UI（注意生成物不适用于小程序，见 docs/03-ui/ui-reference-projects.md E 组）
