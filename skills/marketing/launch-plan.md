# 任务目标

接 `phases/07-launch/SKILL.md` 产出的发布弹药包（文案 + 渠道清单），产出**发布周的单渠道执行卡**：每张卡把一个渠道的发布动作落到"谁在几点发什么、发完如何回应"。区别于 plan-launch（定策略），本技能管执行排期。

# 输入

1. 发布弹药包（介绍文案三版、截图清单、反馈入口）
2. 选定渠道（2-5 个；没有就用弹药包里论证过的那几个）
3. 用户可投入的时间（发布日 + 发布周每天能花多久）

# 输出（严格按此结构交付）

```
## 发布周排期表
| 日期 | 渠道 | 动作（发什么版本） | 时间点 | 预计耗时 |
（发布日集中 2-3 个渠道，其余错开到本周后续，避免一天全发完没人接反馈）

## 每渠道执行卡
每渠道一张：
- 发前：账号/版块规则核对（各社区忌讳不同）、文案终稿按该社区语言习惯微调
- 发布：具体动作与文案版本
- 发布后 24h：多久看一次评论、回复模板（感谢/补充/收集反馈三选一）

## 反馈汇总机制
所有渠道的反馈往哪记（一张表：渠道/原话/联系方式），交环节 08 周复盘
```

# 执行步骤

1. 先读 [docs/07-marketing/marketing.md](../../docs/07-marketing/marketing.md) 的渠道分级与公开构建小节
2. 渠道排序按"目标用户密度"而非"流量大小"；发布日不超过 3 个渠道
3. 每渠道核对社区规则（如 V2EX 分享创造节点的发帖规范），把"会被删帖的写法"提前排掉
4. 时间点对齐目标用户的活跃时段（中文社区晚间为多），写进排期表
5. 回复策略先写好模板：发布日情绪波动大，有模板就不会嘴硬或消失
6. 反馈汇总表是硬产出：所有反馈最终要能流进环节 08 的周复盘

# 检查清单（输出前自检）

- [ ] 排期总耗时 ≤ 用户给的时间预算
- [ ] 没有诱导分享/买量/刷量的动作
- [ ] 每渠道都核对了社区规则并写了"忌讳"
- [ ] 反馈汇总机制闭环到环节 08，不是发完就算

# 边界（不要做什么）

- 不重新选渠道、不写新文案（用弹药包成品，要改策略回 `phases/07-launch/SKILL.md`）
- 不承诺增长数字
- 不适用：产品还没过审上线（先走环节 06）；要的是持续期内容系统（用 `content-calendar`）
