# 环节 02 · 产品定义与任务拆解（Spec）

> **解决什么问题**：验证通过后，把"想法"变成"可以开工的规格"。一个人做产品，PRD 是写给三个角色看的：未来失忆的自己、帮你写代码的 AI、以及用来防止你加功能的你。

## 你要做什么

1. **写一页 PRD（半天）**：用 [templates/prd-template.md](../../templates/prd-template.md)。一页写不完说明还没想清楚——细节靠环节 05 开发时按需补充，不靠 PRD 预言一切。
2. **定义 MVP 边界（半小时，但最重要）**：列两个清单——**必须有**（没有它产品不成立）和 **v2 再说**（想到了但砍掉）。每个"必须有"回答：砍掉它会丢用户吗？答"不会"就移到 v2。
3. **拆任务到「≤1 天」**：每个任务是一张卡：`编号 / 做什么 / 完成标准（怎么验收）/ 预估`。任务能被 AI 一次执行完是最好的粒度——这正是后续环节 05 的工作单元。
4. **定里程碑（3 个就够）**：`M1 内部可用 → M2 提审版 → M3 正式发布`。每个里程碑有日期，写进日历。
5. **写给 AI 的开工说明**：把 PRD + 任务卡放进仓库（建议 `docs/specs/` 或项目仓库根目录），并在项目仓库放一份 [AGENTS.md](../../AGENTS.md) 模板——开发环节 AI 直接读它。

## 产出物

- `prd.md`：一页 PRD（模板现成）
- `tasks.md`：任务卡清单（编号 + 完成标准 + 预估）
- `milestones.md`：3 个里程碑与日期（可并入 PRD）

## 完成标准

- [ ] PRD 一页以内，非技术朋友能看懂要做什么
- [ ] MVP 清单里每个功能都通过了"砍掉测试"
- [ ] 任务拆到每个 ≤1 天，且每张卡有可验收的完成标准
- [ ] 3 个里程碑有具体日期

## 常见陷阱

- **写 50 页 PRD 不写代码**：过度规划是拖延的高级形式。一页 + 任务卡足够。
- **MVP 不最小**："再加个登录吧反正很快"——每个"很快"加起来就是一个月。第一版能手动/人工绕过的功能一律绕过。
- **任务粒度是"做完前端"**：这种任务永远"明天完成"。拆到"完成单词列表页，可滚动、显示 20 条、空态有提示"这种验收粒度。
- **没有截止日期**：没有死线的 side project 会做三年。给 MVP 定 4-6 周死线，超了就砍范围不延日期。

## 小程序主线注意点

- **PRD 里就要画清页面流**：小程序页面层级最多 10 层，Tab 只能有 2-5 个——设计阶段（环节 03）前先把页面结构定粗，避免后期重构导航。
- **能力依赖早确认**：PRD 里凡涉及登录（openid）、支付、订阅消息、分享，标注"需要什么接口/资质"，去[官方文档](https://developers.weixin.qq.com/miniprogram/dev/framework/)确认能力边界，别等开发环节才发现个人主体做不了。
- **首版功能对照硬知识自查**：包体积（大资源上云）、iOS 虚拟支付限制（会员解锁类功能注意）在定义阶段就要有预案。
