# 任务目标

为已发布、进入常态运营的产品搭一套**周更内容系统**：内容主题池、每周生产流水线、最低可行节奏。目标是"三个月后还在更"，不是"第一周爆发"。

# 输入

1. 产品与目标用户（一句话定位）
2. 可投入时间（每周几小时；诚实数字，按 70% 打折排期）
3. 已有素材：CHANGELOG、周复盘、用户反馈（环节 08 的产出就是内容原料）
4. 主阵地（1-2 个；多了必然断更）

# 输出（严格按此结构交付）

```
## 主题池（4 类轮换）
| 主题类型 | 内容来源 | 例子 |
更新日志 / 踩坑复盘 / 用户故事与反馈 / 行业观察——每类给 3 个具体选题

## 周流水线（每周固定 2-3 小时）
周一 30 分钟：从本周 CHANGELOG/复盘中选 1 个主题
周三 60 分钟：写成稿（给每种主题一个段落模板）
周五 30 分钟：发布到主阵地 + 精华转发到次阵地

## 最低可行节奏
断更保护线：忙疯时只做"CHANGELOG 一段 + 一句感想"的 15 分钟版——活着比优雅重要

## 度量与退役线
看什么（阅读/转化/私信量）；连续 6 周某主题无反馈就从主题池退役
```

# 执行步骤

1. 先读 [docs/07-marketing/marketing.md](../../docs/07-marketing/marketing.md) 的公开构建与内容模板（进展帖/经验帖/数据帖三式）
2. 主题池从"你已经每周在产出的东西"里长出来（CHANGELOG、周复盘）——内容系统是环节 08 复盘的下游，不是额外负担
3. 每种主题给固定段落模板（开头一句结果/中间过程与代码块/结尾一句下一步），把"每次从头想写什么"的时间省掉
4. 排期按 70% 打折后的时间；主阵地只选 1 个，次阵地只是转发
5. 写清退役线：内容系统的敌人不是写不好，是悄悄停更

# 检查清单（输出前自检）

- [ ] 主题池的每条选题都有明确的内容来源（不是"想一个"）
- [ ] 周流水线总时长 ≤ 用户给的时间 × 0.7
- [ ] 有断更保护线（最低可行版本）
- [ ] 内容不泄露用户隐私（用户故事需授权或匿名化）

# 边界（不要做什么）

- 不安排发布周（那是 `launch-plan`；本技能管发布后的常态）
- 不做日更承诺、不追热点日历（单人不可持续）
- 不适用：还没有真实素材（CHANGELOG/复盘为空时先跑两周产品迭代再来）；目标是视频/播客等重制作形式（先用文字跑通再升级）
