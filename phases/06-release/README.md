# 环节 06 · 部署与上线（Release）

> **解决什么问题**：把"你自己手机上能跑"变成"通过审核、任何人能搜到能用"，并配好出问题时能发现、能回滚的基础设施。小程序上线 ≈ 80% 合规动作 + 20% 技术。

## 你要做什么

1. **上线前检查（半天）**：走一遍 [skills/devops/deploy-checklist.md](../../skills/devops/deploy-checklist.md) ✅ + 小程序专属项（见下）。
2. **合规三查（小程序重点）**：
   - **类目**：服务类目与实际功能一致，需资质的类目提前备好证明
   - **隐私**：后台配置[用户隐私保护指引](https://developers.weixin.qq.com/miniprogram/dev/framework/user-privacy/)，与代码里实际采集的信息一致
   - **内容**：没有诱导分享、诱导关注、测试版文案（"敬请期待"大量留空页面是高频被拒原因）
3. **发布流程**：开发者工具「上传」→ MP 后台设为**体验版**（自己 + 3-5 个真实用户用 2-3 天）→ 修完问题 → **提交审核**（填写功能页面截图与说明，如实描述）→ 审核通过 → **全量发布**。通常几小时到 2 天（以官方时效为准）。
4. **可观测性（上线当天必须就位）**：
   - 微信后台「[运维中心](https://mp.weixin.qq.com/)」看 JS 错误、接口失败——这是你免费的 APM
   - 云开发/服务器侧：错误日志有地方看、数据库有自动备份
   - 一个 Open问题报警渠道：至少把后台「错误通知」绑到能及时看到的微信/邮箱
5. **回滚预案**：发布前记下当前线上版本号；新版出 P0 问题时，后台可回退版本（回滚是常规操作，不是事故）。

## 产出物

- 正式发布的小程序版本（有版本号、发布备注）
- 一页 `release-checklist.md`（本次发布踩过的坑，下次直接复用）
- 备份与回滚说明（一句话级别即可：备份在哪、怎么回滚）

## 完成标准

- [ ] 审核通过并全量发布，陌生手机搜索可用
- [ ] 体验版阶段有 ≥3 个非开发者真实用过 2 天
- [ ] 运维中心已能看到线上错误，报警能触达你
- [ ] 知道怎么回滚（发一个上一版本号即可）
- [ ] release-checklist.md 存在且可复用

## 常见陷阱

- **自己验完直接提审**：没有真实用户用过体验版。你测出的是"bug"，他们测出的是"看不懂"。
- **提审描述与实际不符**：审核员按你填的功能说明对照实际功能，夸大或描述错类目 = 拒审重来（一轮 1-2 天）。
- **以为上线就结束了**：上线是环节 07 的开始。没有监控的上线等于闭眼开车。
- **首次发布追求完美**：审核被拒 1-2 次是常态，按驳回意见改了再提即可，别 panic 重构。
- **忘了恢复调试开关**：开发时关掉的"校验合法域名"、开的调试模式，提审前必须恢复生产配置。

## 小程序主线注意点

- **域名配置**（自建后端时）：HTTPS + ICP 备案 + 后台「开发管理 → 服务器域名」配置 request/uploadFile/downloadFile 合法域名；**每月修改次数有限制**（以官方为准），改前想清楚。
- **审核高峰**：节假日前后变慢；大版本避开周五提审（周末审核慢，问题反馈滞后）。
- **灰度发布**：正式发布可选"分阶段放量"（以官方后台能力为准），个人项目用户少通常全量即可，但要知道有这个选项。
- **版本管理习惯**：每次提审前在 CHANGELOG 里写清"这版改了什么"，审核被拒时你能快速定位该改哪。
- **云开发环境**：区分测试/生产环境（或至少区分数据集合），别让测试数据混进线上库。
