# 0002 - SKILL 采用纯 Markdown + AGENTS.md 约定

- **状态**：已接受
- **日期**：2026-09-18
- **决策人**：作者本人

## 背景

用户日常使用多个 AI 编码代理（Claude Code、Codex、Cursor、ZCode 等），希望每个环节沉淀的「技能」能被**任何一个代理**直接执行，而不是绑定某个工具。各工具的技能机制不同：Claude Code 有 SKILL.md（frontmatter 含 name/description），Codex/Cursor 等普遍支持读取仓库根目录的 `AGENTS.md` 开放约定，其他工具至少都能读 Markdown 文件。

## 决策

1. 技能文件统一命名为 `SKILL.md`，放在各环节目录内（`phases/XX-xxx/SKILL.md`）。
2. 格式为**纯 Markdown**，frontmatter 只用兼容性最好的两个字段：`name`、`description`（与 Claude Code 的 Skill 约定一致；其他工具会将其视为普通 YAML，无副作用）。
3. 技能内部结构固定六段：**任务目标 / 输入 / 输出 / 执行步骤 / 检查清单 / 边界**——这是「提示词 + 工作流 + 验收标准」的最小完备集。
4. 仓库根目录提供 `AGENTS.md`，向所有代理声明：仓库结构、写作约定、如何找到并执行各环节的 SKILL.md。
5. **不使用任何工具专属语法**（如某工具的斜杠命令、专属变量、API 调用格式）。

## 理由

- 纯 Markdown 是所有 AI 代理的最大公约数：写一次，处处可执行。
- 「输出契约」（输出一节）是关键：AI 的产出只有格式可验收，环节之间才能像流水线一样衔接（01 的输出 = 02 的输入）。
- 放弃的方案：
  - 用某一家工具的专有技能格式 → 锁死生态，换工具就失效
  - 每个工具复制一份定制版 → 内容漂移，维护成本翻倍

## 后果

**正面**：
- Claude Code / Codex / Cursor / ZCode / Hermes 等任何能读 Markdown 的代理都能执行同一份技能
- 技能文件本身也是人可读的 SOP，脱离 AI 也有价值

**负面 / 代价**：
- 用不了工具专属能力（自动触发、参数传递），触发方式是「人把技能文件喂给代理」
- 输出质量的下限取决于所用的模型，无法在文件层面强制
