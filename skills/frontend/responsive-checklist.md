# 任务目标

对一个已实现的页面（截图或可运行预览）做**多端适配检查**，输出问题清单与修法。Web 查断点与移动端；小程序查小屏 iOS / 安卓 / 长屏三档真机。

# 输入

1. 页面（截图一组或可访问的预览）
2. 平台：Web（给断点）或小程序（给机型档位）
3. 核心操作是什么（检查以"操作可达"为准，不以"像素一致"为准）

# 输出（严格按此结构交付）

```
## 检查矩阵
| 检查项 | 尺寸A | 尺寸B | 尺寸C |
（每格 ✅ / ❌+一句话问题）

## 问题清单（按严重度）
每条：现象 / 触发尺寸 / 修法（flex 布局调整、字号缩放、横滑改换页等具体做法）

## 需要真机确认的
列出只能真机验证的项（手势、滚动、安全区、键盘弹起），给出测试步骤
```

# 执行步骤

1. 先读 [docs/03-ui/ui-design.md](../../docs/03-ui/ui-design.md) 的「移动端设计要点」（小程序 750×1334 基准、iOS 393×852、Android 360×800）
2. 三档尺寸逐项查：核心操作可达 / 文字不截断 / 图片不变形 / 底部操作不被安全区遮挡 / 键盘弹起不挡输入框
3. 三个状态（空/载/错）在各尺寸下都查一遍，不只查"有数据"的样子
4. Web 额外查：320px 极小屏、横竖屏切换、触控目标 ≥44px；小程序额外查：iPhone SE 小屏与安卓长屏
5. 模拟器查不出的问题明确列入"需要真机确认"，不假装已验证

# 检查清单（输出前自检）

- [ ] 矩阵没有空格；❌ 项都有修法
- [ ] 修法是具体做法（改什么属性/布局），不是"优化适配"
- [ ] 三态都覆盖了，不只是默认数据态
- [ ] 没有把模拟器结果说成真机结果

# 边界（不要做什么）

- 不改代码（出清单给前端角色执行，写代码用 `phases/05-build/SKILL.md`）
- 不追求多端像素一致（以操作可达与可读为准）
- 不适用：纯桌面后台工具（定死最小宽度即可，别做全面响应式）；页面还没写出来（先开发）
