# 0005 - 角色 = 独立技能树，与任何 Agent 运行时解耦

- **状态**：提议中
- **日期**：2026-09-20
- **决策人**：作者本人（与 AI 讨论后，待作者拍板）

## 背景（Context）

ADR-0002 已确立「技能文件用纯 Markdown、不绑定任何工具」，但**「角色」这一层始终没定义清楚**。

调研多角色 Agent 生态（Superpowers、CrewAI、Claude Squad、VoltAgent）时，主流做法是把角色实现成**运行时实体**：主编 Agent 拆任务 → 启动多个子代理进程并行 → 汇总合并。这条路的隐含前提是：长期使用某一个特定 harness（Claude Code / Codex / Hermes / Cursor），并按它的机制组织角色——子代理调度、worktree 隔离、slash command、编排框架。

这对本仓库不成立：

1. 作者在多个 Agent 之间切换。把「角色」绑到某一个 harness 的运行时机制上，换工具就整套失效。
2. 「一个人 = 一个团队」里的「团队」指的是**分工**，不是**进程**。真正的价值是每个角色的职责边界与交付物定义清楚，而不是同时跑几个进程。
3. 并行的复杂度（工作空间隔离、冲突合并、结果验收）远超单人项目的收益，而且会放大一个已被数据验证的失败模式——「没做用户验证就开建」在 101 场创始人访谈中被提及 11 次，AI 时代只是把犯错速度调快了。

## 决策（Decision）

**角色不实现为运行时实体，而实现为一棵独立、自包含的 Markdown 技能树。**

1. **角色 = 目录**。`skills/<角色>/` 下是该角色的全部技能；每个技能是一个自包含的 Markdown 文件，遵循 ADR-0002 的六段结构（任务目标 / 输入 / 输出 / 执行步骤 / 检查清单 / 边界）。
2. **角色之间靠「输出契约」衔接，不靠调用关系**。A 角色的输出格式 = B 角色的输入格式。这与 phases 环节之间的衔接机制完全一致（ADR-0002 已确立）。
3. **技能文件里不出现任何 harness 特性**——slash command、子代理调度、专属变量、特定工具的 API 一律不用。谁来执行这份技能（人 / Claude Code / Codex / Cursor / Hermes / 未来的任何工具）**与本仓库无关**。
4. **分工明确的判定标准**：任意两个角色之间，能说清「A 交给 B 的是什么文件、什么格式」，就算分工清楚。说不清就是边界模糊——此时先补契约，不要先补技能。
5. **每棵技能树独立演进**。补一个角色的技能不需要动其他角色，也不需要动任何运行时配置。

## 理由（Rationale）

- **与 ADR-0002 同源**：那条解决的是「技能文件不绑工具」，本条把同一原则上提一层到「角色不绑运行时」。解耦的对象从**文件格式**变成**执行方式**。
- 技能树是静态资产，不依赖任何服务存活。三年后回看仓库，这些文件仍然可读可用；而绑定了某个 harness 的编排配置，工具改版就可能失效。
- 角色边界变成**可评审的文本**：分工不清时改的是 Markdown，不是代码。这对单人项目尤其重要——你唯一能依靠的评审工具就是「读一遍」。

考虑过并放弃的方案：

- **方案 A：主编 + 子代理并行**（Superpowers 的路子）→ 收益是快，但单人项目里你只有一个大脑在做验收，同时开三个子代理只是把 review 压力推迟到最后一次性爆发。且 `using-git-worktrees` 这类机制把仓库结构绑死在特定 harness 上。
- **方案 B：引入编排框架**（CrewAI 的路子）→ 它是 Python 库。一旦引入，仓库就从「文档手册」变成了「代码项目」，与仓库定位冲突；而且 Agent 定义写在代码里，就不再是可读的角色说明书。
- **方案 C：多实例 TUI 管理**（Claude Squad 的路子）→ 工具本身好用，但 AGPL-3.0 对商业项目有传染性；且它解决的是「同时看多个进程」，不是「角色分工」本身。

## 后果（Consequences）

**正面**：

- 换任何 Agent、甚至不用 Agent（自己照着做），这套角色分工都成立
- 可以只补一个角色而不动全局，`skills/` 里 15 个 ⏳ 技能能逐个独立补齐
- 角色分工本身就是一份可读的 SOP，脱离 AI 也有价值（与 ADR-0002 的正面后果一致）

**负面 / 代价**：

- 拿不到并行执行的速度收益，一次只能推进一个角色的一个技能
- 没有自动触发与自动串联，每个技能要人显式地「喂」给 Agent 执行——这是 ADR-0002 已承认的代价，此处放大到角色层
- 角色间的交接靠人搬运文件
