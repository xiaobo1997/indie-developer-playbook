# 0004 - 外部链接与事实性内容的收录政策

- **状态**：已接受
- **日期**：2026-09-18
- **决策人**：作者本人

## 背景

各环节的 `references.md` 会收录大量外部链接（开源仓库、官方文档、成功案例）。AI 生成的链接存在「看起来像真的但 404」的风险（幻觉链接）；小程序等平台规则也随时间变化。错误链接会浪费读者时间并损害仓库可信度。

## 决策

1. **只收录经过验证的链接**：加入前必须确认真实存在——首选官方域名（如 developers.weixin.qq.com、github.com 的高 star 仓库），不收录来路不明的内容农场。
2. **优先级排序**：官方文档 > 顶级开源仓库（可运行、star 高、维护活跃）> 一手人物博客 > 社区讨论。每个链接附一句话说明「它是什么、什么场景去看」。
3. **事实性数字必须挂保险**：平台规则、价格、限额等易变事实（如包体积上限、认证费用、审核时长）写作时标注「**以官方文档为准**」，并给出官方文档链接。
4. **链接失效的处理**：发现死链直接删除或替换，不保留 404 链接；`references.md` 是清单不是档案。
5. **成功案例的收录标准**：必须能公开验证其真实性（有公开产品、公开收入或公开源码），收录时写清「谁做的、几个人做的、为什么值得看」。

## 理由

- 本仓库的核心价值是「省读者的甄别时间」，收录政策的本质是质量控制。
- 平台规则类内容天然易腐，「以官方为准 + 链官方」是唯一可持续的写法。
- 放弃「收录越多越好」：清单的价值在信噪比，不在长度。

## 后果

**正面**：
- 读者可以盲点任何链接，默认它是真的、有用的
- 平台规则变化时，维护成本低（改一处、链官方）

**负面 / 代价**：
- 收录速度慢（每个链接要验证）
- 仍有链接自然腐坏，需要定期巡检

**后续动作**：
- [ ] 每季度巡检一次各环节 references.md 的死链
