# 任务目标

接一个产品想法或环节 01 的验证报告，产出**按模板填好的完整 PRD**。与环节 02 的 `write-spec` 的区别：本技能只负责把 PRD 文档本身写规范、写完整，不做任务拆解。

# 输入

1. 产品想法（一两句话）或验证报告
2. 目标用户与核心场景（缺失时先追问一轮）
3. 平台（小程序 / Web / App）

# 输出（严格按此结构交付）

```
## PRD（按 templates/prd-template.md 的 11 节完整填写）
1. 概述（一句话 / 目标用户 / 核心价值 ≤3 条）
2. 背景（为什么做 / 成功指标可衡量 / 非目标）
3. 用户故事（US-1、US-2…每条带验收标准）
4. 功能范围 MVP 表（功能 / 优先级 P0-P2 / 工作量 / 状态）
5. 用户流程（文字流程图）
6. 数据模型（实体 + 字段，草案粒度）
7. API 设计（主要端点草案；小程序云开发则写集合与云函数清单）
8. UI 设计（链接或「待环节 03」）
9. 风险表（≤3 条，含缓解）
10. 决策记录（本 PRD 定稿过程中的关键取舍）
11. 变更日志（初始版本）
```

# 执行步骤

1. 先读 [templates/prd-template.md](../../templates/prd-template.md)，严格按它的 11 节结构，不增删节
2. 先读知识库补充判断依据：[docs/02-product/product-management.md](../../docs/02-product/product-management.md)（MVP 原则、MoSCoW、AARRR）
3. 从输入提取已确认的事实；没有的留 `[待确认]` 占位，**不要编造**
4. 每个功能过砍掉测试：砍掉它产品还成立吗？成立 → 移入非目标
5. 成功指标必须可衡量（时间 + 数值），写不出就是还没想清楚，向用户标红

# 检查清单（输出前自检）

- [ ] 11 节齐全，顺序与模板一致
- [ ] 非目标非空，MVP 表里没有"最好也有"的功能
- [ ] 没有编造的市场数据；未知处均为 `[待确认]`
- [ ] 成功指标有时间 + 数值
- [ ] 全文一页到一页半以内（超过 80 行说明没砍干净）

# 边界（不要做什么）

- 不做任务卡拆解与里程碑排期（用 `phases/02-spec/SKILL.md`）
- 不做 UI 布局设计（第 8 节只放链接或写「待环节 03」）
- 不适用：想法还没过验证（先回 `phases/01-validate/SKILL.md`，本技能不替你验证需求）
