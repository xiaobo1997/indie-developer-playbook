# 多角色技能树 SOP

> 一个人 = 一个团队。**每个角色是一棵独立的技能树**，互不依赖。谁来执行（你自己 / Cursor / Codex / Claude Code / 任何能读 Markdown 的 Agent）与本仓库无关。
> 角色划分参照 obra/superpowers + VoltAgent/awesome-agent-skills + CrewAI；**架构约束见 [ADR-0005](../../docs/decisions/0005-roles-as-independent-skill-trees.md)，格式见 [ADR-0002](../../docs/decisions/0002-agent-agnostic-skills.md)**。
> 创建时间：2026-09-20 · 修订：2026-09-20（去掉 Hermes 主编与并行调度，改为静态技能树）

## 架构：角色是技能树，不是进程

```
skills/multi-agent/        ← 唯一源，只在这里维护
  ├─ orchestrator.md   任务拆分（把功能拆成按角色分工的任务卡）
  ├─ frontend.md       前端角色
  ├─ backend.md        后端角色
  ├─ devops.md         运维角色
  ├─ tester.md         测试角色
  ├─ debugger.md       调试角色
  └─ reviewer.md       审查角色

执行者（随便谁，仓库不关心）：
  ├─ 你自己 —— 照着技能里的清单做
  ├─ Cursor / Codex / Claude Code / 任何 Agent —— 把技能文件喂给它
```

**没有主编进程，没有并行调度，没有派发。** 一次只推进一个角色的一个技能。某个角色的产出（任务卡、测试报告、审查意见）就是交给下一个角色的输入文件。

### 为什么不用「主编 + 子代理并行」

四个理由，详见 ADR-0005：

1. **绑死 harness**。子代理调度、worktree 隔离、slash command 都是某个工具的专属机制，换工具整套失效——这是 ADR-0002 放弃「工具专属格式」时的同一个理由，只是这次解耦的对象从**文件格式**变成了**执行方式**。
2. **review 压力只会推迟，不会消失**。你只有一个大脑在验收，同时开三个子代理只是把压力堆到最后一次性爆发。
3. **会放大已验证的高频失败模式**。「没做用户验证就开建」在 101 场创始人访谈中被提及 11 次，AI 只是把犯错速度调快了——想清楚之前开并行，等于更快地做错东西。
4. **许可证风险**。多实例 TUI 管理器里有 AGPL 协议的（如 claude-squad），商业项目用起来有传染性。不依赖它，就不受它约束。

## 角色清单与交接契约

| 角色 | 技能文件 | 收什么（输入） | 交什么（输出） |
|---|---|---|---|
| 任务拆分 | `orchestrator.md` | 一句话需求 | 按角色分工的任务卡 + 依赖关系 |
| 前端 | `frontend.md` | 任务卡的「前端」部分 | 改动清单 + 自测结果 + 验收步骤 |
| 后端 | `backend.md` | 任务卡的「后端」部分 | 同上 |
| DevOps | `devops.md` | 任务卡的「运维」部分 | 同上 |
| 测试 | `tester.md` | 任务卡 + 业务代码（只读） | 测试报告 + 结果 + 遗留问题 |
| 调试 | `debugger.md` | 复现步骤 + 报错 | 根因 + 修复 + 回归验证 |
| 审查 | `reviewer.md` | 待审改动 | 审查意见（阻塞 / 建议 / 通过） |

**分工是否清楚，只看一条**：上表「交什么」能不能对上下一行的「收什么」。对不上就是边界模糊——此时先补契约，不要先补技能。

## 怎么用

1. 需要哪个角色，就把哪个角色的技能文件喂给你正在用的 Agent（或自己照着做）
2. 技能里「输出」一节就是交给下一个角色的契约，按那个格式收
3. 一次只推进一张任务卡，验收通过再领下一张

不需要在任何工具里「安装」什么。如果某个工具要求技能必须放在它的目录下，用**符号链接**指向 `skills/multi-agent/`，不要复制——复制必然漂移（见下）。

## 关键原则

1. **角色之间靠输出契约衔接**，不靠调用关系
2. **技能文件里不出现任何 harness 特性**——没有 slash command、没有 `delegate_task`、没有子代理调度、没有专属变量
3. **任务卡原则**——一张卡一次交付，验收通过再领下一张
4. **不越界**——任务卡之外的改动要显式声明
5. **唯一源**——只维护 `skills/` 下这一份；`.cursor/` `.codex/` `.claude/` 下如需出现，一律用符号链接，禁止复制
