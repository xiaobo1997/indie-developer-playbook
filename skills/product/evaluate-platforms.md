# 任务目标

回答"**这个产品应该做什么端、用什么跨端路线**"两个问题，并给出**从构建到用户手上**的完整路径与总账（周期×费用）。产出必须能直接被两个下游消费：`phases/02-spec`（功能范围按端裁剪）和 `skills/ship`（发布管线的参数来源）。

# 输入（缺失项一次性问齐，不猜）

1. 产品一句话定位 + 核心玩法/功能形态（工具？内容？游戏？社交？）
2. 目标用户：国内/海外、年龄层、聚集地
3. 变现设想：广告 / 内购 / 订阅 / 买断 / 还没想
4. 身份现实：个人主体 or 有营业执照
5. 已有代码：无 / Web（什么栈）/ 原生小程序 / 其他跨端（什么框架）
6. 预算（一次性 + 月度）与时间盒
7. 是否有 Mac（iOS 构建相关）

# 输出（严格按此结构交付）

```
## 端组合推荐
| 优先级 | 端 | 理由（用户在哪/变现通道/复用现有代码） | 一次性成本 | 周期门槛 |
P0 首发 ≤2 个端（单人同时做超过 2 个端 = 什么都没有）
P1 二期 / P2 观望，各附触发条件（"H5 日活破 500 再上 App"）

## 跨端路线 trade-off（选型决策）
推荐路线 + 被放弃的 2-3 条，每条写清：得到什么 / 付出什么 / 什么时候会后悔

## 每端完整路径（构建 → 打包 → 发布 → 部署 → 提审）
每端一行流水：构建命令 → 产物 → 分发/上架动作 → 提审方式 → 负责技能链接
（逐条引用 platforms/*.md 与 docs/10-platforms，不复制内容）

## 总账
一次性费用合计 / 月度费用合计 / 关键路径周期（含备案、软著、闭测等排队项）
按"今天开工"给出里程碑日期表

## 风险与前置
3 条以内最可能翻车的点（含平台政策类，标注以官方为准）

## 下一步
选端定案 → phases/02-spec 裁剪功能范围 → 有代码则跑 skills/ship/feasibility-check → ship 执行
```

# 执行步骤

1. 先读 [docs/04-frontend/multi-platform-build.md](../../docs/04-frontend/multi-platform-build.md) 的决策树与对照表——本技能是其可执行版；平台规则细节读 [docs/10-platforms/](../../docs/10-platforms/README.md)
2. **端评估**：对每个候选端过一遍「端价值表」（见下），只保留"目标用户真实聚集 + 变现通道匹配 + 身份/预算允许"的端
3. **路线评估**：用下方 trade-off 表，结合"已有代码形态"定路线；已有可复用代码时，重写成本 > 迁移成本才建议换
4. **裁剪 P0**：单人首发端 >2 个时强制砍——用「先验证再扩端」叙事替代"一次全上"
5. 逐端写出完整路径（引用技能，不复制管线内容），排里程碑日期（今天 + 各周期门槛）
6. 汇总总账与风险；明确"下一步交给谁"

## 端价值表（评估用速查）

| 端 | 触达 | 变现 | 费用 | 周期门槛 | 个人主体约束 |
|---|---|---|---|---|---|
| 微信小程序 | 微信生态+搜一搜 | 广告（流量主 UV≥1000）；支付需企业 | ¥0 | 审核 1-3 天 | 不能微信支付；部分类目受限 |
| 微信小游戏 | 微信社交裂变 | 广告+内购（内购需企业） | 软著 ¥500-1000 | **软著 1-3 个月** | 内购受限 |
| H5/Web | 全网、无分发壁垒 | 全通道（海外 Stripe 等） | 服务器 ¥40-300/月 | 国内需备案 7-20 天 | 无审核 |
| iOS | 海外+国内高付费层 | 内购/订阅/买断（最强国度） | $99/年 | ASC 审核 1-3 天 | 需 Mac（EAS 可免） |
| Android GP | 海外 | 内购/订阅/广告 | $25 | 新个人号闭测 14 天 | 测试员要求 |
| 国内 Android | 国内非微信用户 | 广告/内购 | 多数免费+软著 | 多商店 1-7 天/店 | 软著常见要求 |
| Steam | 全球 PC 玩家 | 买断/DLC | $100/App | 商店审核 3-5 工作日 | 需可执行包 |

## 跨端路线 trade-off 表（决策依据）

| 路线 | 得到 | 付出 | 什么时候会后悔 |
|---|---|---|---|
| **Taro**（React 系） | 小程序+H5 一套代码；RN 出 App；React 生态与 AI 友好 | App 端成熟度中等；多端差异要写分支 | App 成为绝对主力、需要重度原生能力时 |
| **uni-app**（Vue 系） | 小程序+H5+App 全覆盖；国内资料最多 | App 靠 DCloud 生态绑定；海外场景弱 | 产品出海、或想脱离 DCloud 工具链时 |
| **Expo（RN）** | 原生控件体验；EAS 云构建**免 Mac 出 iOS 包**；OTA 更新 | 不支持小程序；EAS 云构建额度（免费档以官方为准） | 想进微信生态时（要从头再来） |
| **Flutter** | 性能与 UI 一致性上限高；五端一套 | Dart 学习成本；包体偏大；小程序支持不成熟 | 团队只有 Web 背景、或必须做小程序时 |
| **Capacitor** | 已有 Web 一周出 App；插件生态 | WebView 性能上限；重交互体验打折 | 产品是重动画/重图形应用时 |
| **Tauri 2.0** | 桌面包极小、内存省；移动端新支持 | Rust 门槛；移动端生态年轻 | 只要移动端不要桌面时 |
| **Cocos Creator** | 游戏：小游戏+移动端+桌面一套工程 | 仅适合游戏形态 | 做的是工具/应用时 |
| 原生双端（Swift+Kotlin） | 体验与平台能力天花板 | 两套代码，单人不划算 | 有收入后单端重写时（可行路径，不是起点） |

# 检查清单（输出前自检）

- [ ] P0 首发 ≤2 个端，且每个都答得出"目标用户为什么在这个端上"
- [ ] trade-off 表里被放弃的路线都有"什么时候会后悔"——这是给未来的自己的保险
- [ ] 每端完整路径都引用了具体技能/文档（ship 管线、部署清单），没有凭空步骤
- [ ] 总账含周期门槛（备案/软著/闭测）并给了里程碑日期
- [ ] 已有代码时，评估过复用/迁移/重写三个选项的成本
- [ ] 平台政策类结论都标了"以官方为准"

# 边界（不要做什么）

- 不写代码、不搭脚手架（定案后：脚手架走 `phases/04-setup/SKILL.md`）
- 不做发布动作（那是 `skills/ship` 的事；本技能的路径表是给它的输入）
- 不替用户拍板商业决策（变现方式摇摆时给两套端组合方案，让用户选）
- 反向触发：用户已明确端与路线且只要执行 → 跳过本技能，直接 `feasibility-check` + `ship`
