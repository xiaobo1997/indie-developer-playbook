# 08 - 客服支持

## 独立开发者的客服挑战

- 没预算雇客服
- 用户期望 24/7
- 一个差评可能毁掉产品

## 客服原则

### 1. 快速回复
- 24 小时内必回
- 复杂问题也要回：先说"我处理中"

### 2. 同理心
- 用户说"烂"，他可能真的很不爽
- 道歉 + 解决 > 解释
- 不要争论

### 3. 公开透明
- 公开 roadmap
- 公开 bug 状态
- 公开已知问题

### 4. 把支持变成 insight
- 客服问题 = 产品洞察
- 记录高频问题
- 写 FAQ

## 客服渠道

### 自助优先

#### FAQ / 帮助中心
- 工具：**HelpScout Docs**、**GitBook**、**Notion**
- 内容：
  - 入门指南
  - 常见问题
  - 视频教程
  - 更新日志

#### 视频教程
- YouTube 频道
- 短视频（TikTok / Reels）
- 录屏教程

#### Chatbot
- 工具：**Crisp**、**Tawk**、**Intercom**
- 处理 80% 简单问题

### 人工支持

#### 邮件
- 主要渠道
- 工具：**HelpScout**、**Front**、**Gmail**
- SLA：24 小时回复

#### 实时聊天
- 工具：**Crisp**、**Intercom**
- 适合：付费用户

#### Discord / 微信群
- 社区支持
- 用户互助
- 注意：会占用很多时间

#### GitHub Issues
- 适合：开发者产品
- 公开透明

## 客服工作流

### 标准流程

```
1. 用户提问
   ↓
2. 自动确认收到（"我们 24 小时内回复"）
   ↓
3. 内部分类（bug / 咨询 / 投诉）
   ↓
4. 分配给对应人
   ↓
5. 回复
   ↓
6. 跟进（"问题解决了吗？"）
   ↓
7. 标记完成
   ↓
8. 写 FAQ（如果是常见问题）
```

### 回复模板

#### 感谢 + 道歉
```
感谢反馈！[用户提到的问题]确实是我们没做好，
非常抱歉给你带来困扰。[解决方案]。
```

#### 已知问题
```
这是已知问题，我们在 [JIRA/Linear] 中跟踪。
预计 [时间] 修复。
临时方案：[workaround]。
```

#### 需要更多细节
```
感谢反馈！为了更好地帮助你：
1. 你的 [环境/版本]
2. 截图/录屏
3. 复现步骤
```

#### 关闭工单
```
很高兴解决了！如果还有其他问题，随时找我。
顺便：[相关文档链接]
```

## 危机管理

### 严重事件处理

#### 服务宕机
```
1. 立即在 Status Page 更新
2. Twitter 公告
3. 邮件通知付费用户
4. 修复后详细复盘
```

#### 数据泄露
```
1. 立即修复漏洞
2. 通知受影响用户
3. 公开说明（避免谣传）
4. 改进安全流程
```

#### 差评 / 公关危机
```
1. 公开、专业、不情绪化
2. 承认问题（如真有错）
3. 说明改进措施
4. 不要删除差评
```

### 预防
- 定期做 incident response 演练
- 准备 runbook
- 培养"先沟通后修复"的习惯

## 客服 vs 产品

### 什么时候改产品
- 同问题每周 > 3 次
- 老用户也卡在这
- 改产品比回复更有效

### 什么时候不改
- 个别用户的特殊需求
- 已经做了的（教会用户）
- 优先级低

---

## 客服指标

### 关键指标
- **响应时间**：首次回复 < 24h
- **解决时间**：< 48h
- **CSAT**（满意度）：> 4/5
- **NPS**（推荐度）：> 50

### 工具
- HelpScout Reports
- Intercom Analytics
- Hotjar（看用户真实行为）
