# 任务目标

接环节 02 的 PRD，产出：**页面清单（含组件映射）+ 一页设计约定（design tokens）+ 关键页布局方案**。全部基于一个选定组件库，禁止发明该组件库没有的复杂自定义交互。

# 输入

1. 环节 02 的 PRD（页面结构粗稿、MVP 功能清单、非目标）
2. 目标平台（小程序 / Web）与选定组件库（若未选，按平台推荐一个并说明理由）
3. 品牌色偏好（若有；没有就替用户选 2 个候选并说明气质差异）

# 输出（严格按此结构交付）

```
## 页面清单
| 页面 | 用户进来做什么 | 离开时完成什么 | 所需组件（组件库名称） | 异常状态（空/载/错） |
（覆盖 PRD 所有页面；Tab 页标注）

## 设计约定（design-tokens.md 内容）
- 主色/辅助色（hex）、语义色（成功/警告/危险）
- 字号阶梯、间距阶梯、圆角
- 统一处理：空态文案模板、加载方案（骨架屏/转圈）、错误与重试
- 深色模式：做/不做的明确决定与理由

## 关键页布局方案
对 3 个核心页面各给：
- 布局结构描述（从上到下分区）
- 所用组件清单
- 一个参考的成熟产品模式（如"设置页参考 iOS 分组列表样式"）

## 交给开发的备注
3 条以内：开发环节最容易做偏的视觉点
```

# 执行步骤

1. 通读 PRD，把页面结构粗稿展开成完整页面清单；对照 MVP 清单确认没有多余页面
2. 查选定的组件库（基于你掌握的组件库知识），为每个页面的每个区块指定现成组件；组件库没有的区块，用最简单的原生写法兜底并标注
3. 为每个页面定义三种异常状态的处理（可直接复用统一模板）
4. 制定设计约定：给出具体数值（hex、px/rpx、间距阶梯），不写"合适的留白"这类不可执行的话
5. 对关键页输出布局方案，并给一个可参考的成熟产品模式（凭你已知的公开产品，不要编造链接）
6. 深色模式给明确决定（默认"本版不做"并说明），平台为小程序时提醒真机验证字号间距

# 检查清单（输出前自检）

- [ ] 每个页面都映射了具体组件名，没有"一些卡片"这种模糊描述
- [ ] 空/载/错三种状态全部覆盖，无一页遗漏
- [ ] 设计约定全是可执行数值，没有形容词
- [ ] 没有超出组件库能力的花哨交互；平台约束（如小程序 Tab 2-5 个）已满足
- [ ] 未编造参考链接；提到的成熟产品模式是公开可验证的

# 边界（不要做什么）

- 不产出高保真像素稿（写代码时用真组件迭代，草图粒度足够）
- 不改 PRD 的功能范围（发现页面/功能矛盾时，输出"待用户确认"清单而不是自行取舍）
- 不引入第二个组件库或自定义主题引擎
