# 让 AI 当你的设计师

> **核心主张：不要把「设计」当成一个独立阶段。** 它是一串连续的收敛动作，从「怎么用」一路收敛到「长什么样」，中间没有一道墙。
>
> 配套阅读：[prototype-first.md](prototype-first.md)（核心功能守门与页面清单）、[ui-reference-projects.md](ui-reference-projects.md)（去哪找参考）。本页讲的是**怎么驱动 AI 完成这整条链**。

## 完整流程

```
产品需求
  ↓
用户流程
  ↓
低保真原型        ← 解决「怎么用」
  ↓
Design System    ← 解决「怎么保持一致」
  ↓
高保真 UI        ← 解决「长什么样」
  ↓
代码
  ↓
真实产品截图 ──→ 回给 AI 评审 ──→ 继续调整   ← 闭环，别漏
  ↓
Icon Library     ← 贯穿全程，解决「怎么快速完成细节」
```

**四个层次各管一件事，不要混**：

| 层 | 解决什么 | 不问什么 |
|---|---|---|
| 原型 | **怎么用** | 不关心颜色好不好看 |
| UI | **长什么样** | 不关心流程走不走得通 |
| Design System | **怎么保持一致** | 不关心具体页面 |
| Icon Library | **怎么快速完成细节** | 不关心结构 |

最常见的翻车方式就是混层：在原型阶段讨论配色（过早），或在高保真阶段才发现流程走不通（过晚）。

## 给 AI 的 prompt：要分层输出，别要「漂亮网站」

### 反例（会得到 Dribbble 页面）

> ❌ 「帮我设计一个漂亮的网站，做给独立开发者用的收入分析 SaaS。」

这会得到一个**看起来漂亮但无法真正开发的东西**：没有真实数据结构、没有空态、组件是你组件库里没有的、间距是随手给的。它的用途仅限于截图发朋友圈。

### 正例（分层收敛）

```
我要做一个 [产品一句话定义：帮谁用什么方式完成什么事]。

请按以下顺序输出，每完成一步等我确认再进入下一步：

1. 信息架构：有哪些模块，模块之间什么关系
2. 页面列表：每页路由 + 一句话职责（一页只做一件事）
3. 每页布局：分区块描述（顶部 / 主体 / 底部），标注每块放什么
4. 组件列表：每块用 [组件库名] 里的哪个现成组件
5. Design Tokens：主色、圆角、字号阶梯、间距阶梯
6. UI：基于以上生成页面

约束：
- 风格参考 [某产品]，[简洁 / 专业 / 偏暗色]
- 每个页面必须给出空态、加载、错误三种状态
- 不要发明新交互，用 [组件库] 已有的模式
- 组件必须是 [组件库] 里真实存在的，不存在的就说明需要自己写
```

差别在哪：**反例要的是结果，正例要的是过程**。过程被拆开后，每一步你都能拦住它——尤其第 4 步，能直接筛掉那些「看起来有、实际没有」的组件。

## 闭环：把真实截图回给 AI 评审

这一步最容易被漏，但价值最大——**AI 生成的是方案，真实产品才是答案**。浏览器渲染、真机字号、数据撑开后的布局，只有跑起来才看得到。

### 评审 prompt

```
这是我已经实现的页面截图。请按以下维度检查，只报问题，按严重程度排序，不要泛泛夸：

1. 信息层级：想象转成黑白，重点还清楚吗（靠颜色救的结构要改结构）
2. 间距一致性：同类元素的间距是否统一
3. 对齐：有没有元素没对齐到同一条线
4. 对比度：文字与背景对比是否足够
5. 状态覆盖：空态 / 加载 / 错误有没有处理
6. 数据极端情况：文字很长、列表很多、数字很大时会不会破版

每个问题给出具体的改法（改哪个值、改成什么），不要只说「建议优化」。
```

「不要泛泛夸」这句很重要——默认状态下 AI 会先夸一轮，那一段全是噪音。

## 关于 Figma：视觉确认 ≠ 像素精修

这里要划清一条线，否则会自相矛盾：

| 用法 | 判断 |
|---|---|
| **视觉确认**：把 AI 生成的方案摆出来看一眼，判断方向对不对 | ✅ 值得做，尤其在你看不出「好不好看」的时候 |
| **像素精修**：在 Figma 里花几天调间距、对齐、圆角 | ❌ 负资产——写代码时反正要重排，且组件库会替你决定大部分值 |

判断标准：**只做「确认方向」，不做「定义细节」**。细节交给组件库的默认值（见 [prototype-first.md](prototype-first.md) 第 4 步：只做三个决定）。

同理，[OpenDesign](https://github.com/nexu-io/open-design)（★97,204，Apache-2.0）这类 Agent 设计工具，它的位置也在**高保真 UI 这一层**——用来看观感，不是用来定结构。

## Icon Library：贯穿全程，别临时找

图标是最容易在最后拖慢进度的东西——每个图标看着都差不多，挑起来却很费时间。**一开始就定死一个库，全程只用它的**：

- [heroicons](https://heroicons.com/) —— 简洁，MIT
- [iconify](https://iconify.design/) —— 海量图标聚合，一个库涵盖几乎所有图标集
- 小程序：优先用 TDesign 自带的图标，别混外部库

**不要自己画图标。** 每个 30 分钟起步，而且一定和组件库的视觉风格打架——这是 [prototype-first.md](prototype-first.md) 里「反花哨」清单的第一条。

## 检查清单

- [ ] 要的是分层输出，不是「帮我设计一个漂亮的网站」
- [ ] 信息架构 → 页面列表 → 布局 → 组件 → tokens → UI，每步都确认过再往下
- [ ] 组件列表里的组件在你选定的组件库里真实存在
- [ ] 每页的空 / 载 / 错三态都定义过
- [ ] 图标库一开始就定死，且只有一个
- [ ] **代码写完把真实截图回给 AI 评审过**（这一步最容易漏）
- [ ] 评审 prompt 里写了「不要泛泛夸」
