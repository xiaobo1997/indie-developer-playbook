# 0003 - 第一平台主线：微信小程序

- **状态**：已接受
- **日期**：2026-09-18
- **决策人**：作者本人

## 背景

本仓库既是一份通用独立开发者手册，也服务于作者本人**正在从零开发微信小程序**的现实。学习路径需要一个主战场：内容太通用则无法落地，太特化则失去手册价值。

## 决策

1. `phases/` 的 8 个环节写**通用方法论**，每个环节内增设「**小程序主线注意点**」小节，承载小程序特有的硬知识（主体资质、域名备案、审核规则、包体积等）。
2. 平台专属的完整内容仍归 `docs/10-platforms/wechat/`，环节文档只链接不复制。
3. 举例优先用小程序生态：组件库举 TDesign/Vant Weapp/WeUI，后端举微信云开发，发布讲审核与体验版。
4. Web SaaS 路线保留为第二主线（未来 App / 独立网页产品时启用），在环节文档中以「Web 路线」小字标注。

## 理由

- 作者当前的项目就是小程序，知识记录应**直接服务正在做的事**，学完即用。
- 小程序是国内独立开发门槛最低的起点之一：免服务器起步（云开发）、分发内置（微信搜索/分享）、支付体系现成。
- 放弃「只写通用内容」：通用内容网上已有大量同质化手册，价值不高；结合小程序的从零记录才是本仓库的差异化。

## 后果

**正面**：
- 学习与建设合一：做小程序过程中踩的坑直接沉淀进对应环节
- 后续做 App / Web 时，环节方法论可复用，只需替换平台注意点

**负面 / 代价**：
- 部分环节（如 06 上线）内容偏小程序，Web 路线读者需自行跳转 docs/10-platforms
- 小程序官方规则变化频繁，文档需持续校对（以官方文档为准，见 ADR-0004）

**后续动作**：
- [ ] 每次小程序实操后，把新踩的坑回写到对应环节的 README「小程序主线注意点」
