# 任务目标

接环节 02/03 的产出，产出：**选型决策表 + 项目骨架 + 项目版 AGENTS.md + 环境跑通清单**。目标是一个能被用户亲手跑通真机预览的空项目，而不是一堆框架选项的科普。

# 输入

1. PRD 与设计约定（环节 02/03 产出）
2. 用户现状：操作系统、会什么语言、有没有服务器/备案域名、小程序 AppID 是否已注册
3. 时间预算与是否考虑未来多端

# 输出（严格按此结构交付）

```
## 选型决策表
| 决策点 | 选择 | 一句话理由 | 放弃的选项与原因 |
（决策点：前端路线/后端路线/包管理/代码规范工具；默认给保守答案）

## 项目骨架
目录树 + 每个文件的一句话说明 + 关键配置文件内容（可直接复制的代码块）

## 项目版 AGENTS.md
仿照仓库根目录 AGENTS.md 改写：技术栈/目录约定/代码风格/常用命令/禁止事项

## 跑通清单（给用户亲手做的部分）
按序号列出：注册/下载/安装/初始化/真机预览 每一步，含验证点（"看到 XX 即成功"）
标明哪些步骤必须用户本人操作（如扫码、输密码），AI 不要假装能代劳

## 已知风险
2 条以内（如：云开发额度、某依赖与 Node 版本兼容性），以官方文档为准
```

# 执行步骤

1. 读输入，先判定默认路线是否成立（第一个小程序 + 无特殊诉求 → 原生小程序 + 云开发）；不成立才给替代方案
2. 生成项目骨架：按官方推荐的目录结构；配置文件给完整可复制内容，不留 "...其余略"
3. 写项目版 AGENTS.md：从本仓库根目录版本删掉"手册仓库"专属内容，替换为项目技术栈约定；包含"改完代码自测什么"
4. 写跑通清单：把自己不能替用户做的步骤（下载安装、扫码登录、输 AppID）明确标出
5. 提醒 `.gitignore`（node_modules、密钥、project.private.config.json 等）与首个 commit

# 检查清单（输出前自检）

- [ ] 决策表有默认答案而不是罗列选项让用户自己挑
- [ ] 骨架里没有任何编造的第三方包名/版本号；引用官方 API 处标注"以官方文档为准"
- [ ] AGENTS.md 包含"代码风格"和"禁止事项"，可直接使用
- [ ] 需要用户亲手操作的步骤已明确标出，没有假装 AI 能扫码/注册
- [ ] 给出了密钥与隐私文件不进仓库的具体做法

# 边界（不要做什么）

- 不一次引入多端框架、CI/CD、监控等"以后可能用"的东西（YAGNI）
- 不在骨架里塞业务代码（那是环节 05）
- 用户现状信息不足时先问一轮再输出，不要基于错误假设生成整套骨架
