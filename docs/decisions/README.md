# 决策记录（ADR · Architecture Decision Records）

> 每一次重要的「我们决定怎么做、为什么这么做」都记录在这里。
> 目的：三个月后的你（或者接手的 AI 代理）不用重新推理一遍，只需读决策。

## 什么是 ADR？

ADR（Architecture Decision Record）是一段短文档，记录：
- **背景**：当时面临什么问题
- **决策**：选了什么方案
- **理由**：为什么选它、放弃了什么
- **后果**：这个决定带来什么好处和代价

一条 ADR 只记录**一个决策**，正文尽量短（一屏内），决策一旦写下**不修改只追加**——错了就写一条新的 ADR 把旧的标记为「已取代（Superseded by ADR-XXXX）」。

## 什么时候该写一条 ADR？

满足任意一条就写：
- 这个决定**影响多个目录/环节**（比如目录结构、技能格式）
- 这个决定**很难回退**或回退成本高
- 你在两个方案之间**纠结超过 10 分钟**
- 你希望未来的 AI 代理**沿用这个约定**而不要自作主张

## 什么时候不用写？

- 错别字、格式调整、补一个链接
- 单个文档内部的内容增补
- （这些直接记入 [CHANGELOG.md](../../CHANGELOG.md) 即可）

## 写作规则

1. 文件名：`NNNN-短横线英文标题.md`，编号递增，不复用
2. 新决策追加到上表和 [CHANGELOG](../../CHANGELOG.md) 的 Decisions 小节
3. 中文书写，代码/术语保留英文
4. 模板见 [0000-adr-template.md](0000-adr-template.md)
